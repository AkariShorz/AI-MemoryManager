# AI-MemoryManager

面向 AI 助手的跨平台、模型无关的记忆管理系统。

> **项目阶段：** 目前处于需求整理与方案讨论阶段，尚未确定具体实现架构或客户端接入方式。

## 已确认需求

- **本地优先，由用户掌控：** 默认在本地保存数据；如需同步，由用户自行选择并控制。
- **跨平台方向：** 优先开发 Linux 版本，之后适配 Windows 和 Android。
- **独立的人设档案：** 为每个 AI 身份维护独立档案，包括会持续演变的文字特征和外观参考素材。
- **忠实归档会话：** 按 AI 提供方、人设和日期组织会话；收到或导入的原始消息应保持原样。
- **尽快保存消息：** 消息到达后尽可能立即保存，以减少数据丢失；并每 30 分钟与来源客户端进行一次对账。
- **每日概要与原文回溯：** 通过每日概要定位相关会话，并可按需找回原始会话细节。
- **用户可控的遗忘与删除：** 用户可以要求遗忘或删除指定内容；同时按需删除或更新相关原始记录、概要和索引等衍生数据。
- **灵活接入客户端：** 尽可能自动发现已安装的本地 AI 客户端；无法直接接入时，提供适配器、插件或导入导出等替代方式。
- **后台服务与管理界面：** 提供用于持续管理记忆的后台组件，以及供用户配置和控制的界面。
- **核心功能不依赖云端 AI API：** 核心存储与检索能力应能在不调用云端 AI API 的情况下运行。

## 建议方向（尚未确定）

以下内容是供后续讨论的初步建议，不代表已经确定的需求或设计：

- 将各客户端接入方式设计为可替换的连接器，并明确记录各自支持的能力；不假定所有客户端都能提供本地历史记录。
- 将原始消息与概要、索引、人设笔记等衍生数据分开管理，以便重建或按要求删除衍生数据。
- 同步功能默认关闭；实现前明确同步范围、目标位置和冲突处理方式。
- 从最小可用的 Linux 流程开始：能够接收或导入会话、保留原始内容，并按日期和人设检索。

## 客户端接入边界

每种客户端及其安装方式都需要单独确认可用的接入途径。本项目**不假定 ChatGPT 提供受支持的本地历史记录 API**。如果没有受支持的直接接口，应采用用户授权的导入导出或其他有文档说明的接入方式；不把未公开的私有数据格式当作稳定接口。

## 下一步需要决定的事项

选择首个 Linux 客户端，以及该客户端受支持或由用户控制的会话接入方式。此决定将确定首个小规模原型的范围，同时避免过早锁定整体架构。
